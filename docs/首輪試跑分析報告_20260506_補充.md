# 補充報告：channel 排列順序疑似錯誤

針對使用者提問「motor2 的問題是不是 config 把電壓電流搞混」**結論：機率很高**。本補充報告附證據。

---

## 1. 補充背景

使用者已澄清：
1. DNM-843 = 800V variant、DNM-844 = 1000A variant，**不可變更**。
2. 兩台壓力計 slave id 都是 1，所以 RTU2 timeout 是預期行為（建議 [config.py](../pump_monitor/config.py) 將 `M1_RTU2_ADDR` 改為 `0` 省 1 秒 timeout，或保留 `2` 容忍）。
3. 想知道 motor2 異常數據是不是 V/I 通道搞混。

→ 因此**先前報告中對 DNM843_GAIN 的疑慮排除**；剩下 motor2 的詭異數據才是焦點。

## 3. 三個關鍵不一致

### 3.1 ch3~5 沒有 50 Hz

如果 ch3~5 真的是「motor2 三相電壓」，**不論 motor2 有沒有運轉**，都不該出現「FFT 主頻 2802 Hz」這個現象：
- motor2 有運轉 → 應有強 50 Hz 基波
- motor2 停機 → ADC 應接近 0 / 純白噪聲 / 50/60 Hz 雜訊耦合

實測 FFT 主頻 = 2802 Hz、rms 0.6V、有 transient → 這 **完全是 VFD 載波 switching 訊號**的形貌。電壓量測訊號幾乎不可能長這樣。

### 3.2 ch3~5 跟 ch6~8 形狀「同類」

- ch3~5：rms 0.65、peak ~8、FFT 2802 Hz
- ch6~8：rms 0.31、peak ~7、FFT 1108 Hz

兩組都是「小 rms、中等 peak、kHz 級主頻」 — 這是電流訊號被 VFD switching 主導的典型特徵。**兩組看起來像是同一類量測對象（電流），只是接到不同 VFD 驅動的馬達**。

主頻不同（2802 vs 1108 Hz）正好可以解釋成：**motor1 與 motor2 用不同 VFD 設定 / 不同載波頻率**。

### 3.3 ch9~11 是「浮接」不是「飽和訊號」

ch9~11 的 mean ≈ +9.99 V、99% 樣本貼著 +9.9997 V：這不是訊號飽和（飽和會在 +V 與 -V 之間切換），是 **ADC 輸入端開路被 pull-up 拉到 +Vs**。可能：
- DNM-844 那 3 個輸出 pin 沒接到 I-8014W 輸入
- DNM-844 模組沒供電（輸出端阻抗高 → ADC 內部 pull-up 主導）
- I-8014W 輸入端 jumper 設定錯誤

## 4. 兩種假設的數值對照

### 假設 A（目前 config）：`[V × 6, I × 6]` 排列

```
ch0~2  → motor1 三相 V × 80   = 426 V_rms ✓
ch3~5  → motor2 三相 V × 80   =  50 V_rms ✗（不像電壓）
ch6~8  → motor1 三相 I × 100  =  35 A_rms ✓
ch9~11 → motor2 三相 I × 100  =  ALL +1000 A SATURATED ✗
```

→ motor2 的兩組（V 和 I）**同時都壞掉**，這在硬體上需要兩個獨立故障同時發生，機率偏低。

### 假設 B（疑似真實接線）：`[m1_V, m1_I, m2_V, m2_I]` 配對排列

```
ch0~2  → motor1 三相 V × 80   = 426 V_rms ✓ (50Hz)
ch3~5  → motor1 三相 I × 100  =  60 A_rms ✓ (VFD 2.8 kHz)
ch6~8  → motor2 三相 V × 80   =  28 V_rms ✗（不像電壓）
ch9~11 → motor2 三相 I × 100  → 浮接
```

→ **motor2 沒運轉**（V 通道沒看到 50Hz）+ **motor2 CT/DNM-844 接線異常**（I 通道浮接），單一馬達整體異常 → 機率較高。

並且 **motor1 的 60 A_rms 比 35 A_rms 更接近合理量級**（5–10 HP 三相馬達）。

---

## 5. 還無法 100% 斷言的原因

從訊號特徵 **強烈暗示** 假設 B，但要 100% 確認還需驗證：

1. **看現場 WP-8121 的 I-8014W 端子上的標籤**：哪一個 ICP DAS pin 接到 DNM-843 的哪一相 / DNM-844 的哪一相
2. **motor2 啟動後重測**：如果假設 B 正確，啟動 motor2 後 ch6~8（不是 ch3~5）應該出現乾淨的 50 Hz 強訊號
3. 假設 B 的 motor1 電流 rms 60A 也要與電工現場用鉗形電流表交叉驗證

## 6. 建議的 config 修正（**只在現場驗證後才上**）

[pump_monitor/decoder.py](../pump_monitor/decoder.py) 的 `split_machine2()` 從：

```python
def split_machine2(volts, dnm843_gain, dnm844_gain):
    V = volts[:, 0:6] * dnm843_gain
    I = volts[:, 6:12] * dnm844_gain
    motor1 = np.column_stack([V[:, 0:3], I[:, 0:3]])
    motor2 = np.column_stack([V[:, 3:6], I[:, 3:6]])
    return motor1, motor2
```

改成：

```python
def split_machine2(volts, dnm843_gain, dnm844_gain):
    # 現場接線確認為 [m1_V, m1_I, m2_V, m2_I] 配對排列 (verified YYYY-MM-DD)
    m1_V = volts[:, 0:3]  * dnm843_gain
    m1_I = volts[:, 3:6]  * dnm844_gain
    m2_V = volts[:, 6:9]  * dnm843_gain
    m2_I = volts[:, 9:12] * dnm844_gain
    motor1 = np.column_stack([m1_V, m1_I])
    motor2 = np.column_stack([m2_V, m2_I])
    return motor1, motor2
```

[config.py](../pump_monitor/config.py) 的 `M2_CHANNEL_NAMES` 同步改成：

```python
M2_CHANNEL_NAMES = (
    "motor1_Va", "motor1_Vb", "motor1_Vc",   # ch0~2
    "motor1_Ia", "motor1_Ib", "motor1_Ic",   # ch3~5
    "motor2_Va", "motor2_Vb", "motor2_Vc",   # ch6~8
    "motor2_Ia", "motor2_Ib", "motor2_Ic",   # ch9~11
)
```

`tests/test_decoder_machine2.py` 的「voltage 在前 6 ch、current 在後 6 ch」斷言也要同步修正。

## 7. 其他副發現（記錄但不阻塞）

- **machine2 在連續觸發 12ch×10kHz 時會 FIFO overflow（error_code 203）**：剛才嘗試重複 capture 三次都失敗，PING 仍 PONG、STATUS 為 IDLE。建議：
  - 若需更穩，可考慮把 RATE 調為 8000 Hz/ch（8ch×10k = 80kS/s，machine1 OK；12ch×10k = 120kS/s，machine2 接近極限）
  - 或在 pipeline 中加一個「捕捉失敗時自動重試一次」的策略
- **agent actualSampleRate ≈ 10417 Hz**（不是 10000 Hz）：硬體限制，CSV 的 `t_s` 已用 actual rate 計算，不是 bug。

---

## 8. 結論

**使用者直覺正確。** 觀察到的 motor2 異常**不是兩個獨立故障**，而是 **channel 排列假設錯誤** + **motor2 本身的 CT/DNM-844 接線/供電問題** 的組合。

最可能的真實接線是 `[m1_V, m1_I, m2_V, m2_I]` 配對排列，而非目前 plan 假設的 `[V×6, I×6]` 分離排列。

**建議下一步**：到現場直接看 WP-8121-CE7 machine2 的 I-8014W 端子標籤、確認 ch0–11 對應的物理 pin 名稱與接線，然後依現場真值修改 [decoder.py](../pump_monitor/decoder.py) 與 [config.py](../pump_monitor/config.py)，並加註修正日期。修完後重跑 [run_once.py](../run_once.py) 並用 [pump_monitor/viz.py](../pump_monitor/viz.py) 確認 motor1/2 的 V/I 都呈現乾淨的 50 Hz。
