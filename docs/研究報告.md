# NCKU 水處理廠泵浦監控 DAQ Pipeline — 研究報告

## 1. 研究背景與目的

### 1.1 場域與監測需求

本研究的應用場域為**自來水淨水場**，需長期監測場內兩台**抽水機（pump 1 / pump 2）** 的健康狀態，蒐集以下四類訊號作為深度學習故障診斷模型的訓練資料：

| 物理量 | 取樣率 | 用途 |
|---|---|---|
| 振動加速度（兩軸） | 10 kHz | 軸承劣化、葉輪不平衡之高頻特徵 |
| 三相電壓 / 電流 | 10 kHz | 馬達負載特徵、相位失衡 |
| 出口壓力 | 數 Hz（RTU 一次/cycle） | 流量代理變數 |
| 軸承溫度 | 0.1 Hz（10 分鐘一次） | 機械損耗 / 過熱告警 |

### 1.2 既有架構與限制

現場部署兩台 ICP DAS **WP-8121-CE7** 工業電腦：

- **machine1（192.168.1.12）**：負責振動 4 通道 DAQ 取樣 + 透過 Modbus-RTU 主端讀取兩支壓力計
- **machine2（192.168.1.13）**：負責 12 通道（三相電壓 ×2 馬達 + 三相電流 ×2 馬達）DAQ 取樣

兩台 WP-8121 上同時部署同一份手寫 C++ agent（[daq-cpp-code/daq_agent_wince.cpp](../daq-cpp-code/daq_agent_wince.cpp)），於 TCP port 9000 監聽 `START_CAPTURE` 命令並回傳 bin 封包。溫度則由獨立的 ICP DAS **ET-2215H** RTD 模組（192.168.1.6）以 Modbus-TCP 方式提供。

**重構前的痛點**：
- 既有 `request-example.py` 只示範**單次**抓取 bin 並落地為 raw 二進位檔，未做物理量轉換、未串接成排程器
- 既有 `temp_receiver.py` 為**獨立**程式，每 10 分鐘存一筆溫度到自己的 .bin 檔，與兩台 DAQ 的時間軸完全不同步
- ADC raw（int16）尚未依各感測器手冊轉成實際物理量（g、V、A、bar、°C）
- 沒有**深度學習友善**的 CSV 輸出格式

### 1.3 重構目標

在家用 PC 端建立主動排程器 [pump_monitor/](../pump_monitor/) 套件，每隔 `Tpoll = 600 s`：

1. **同時**對 machine1 / machine2 / ET-2215H 發出取樣請求（並行），各取樣 `SEC = 10 s`，振動/電氣以 `RATE = 10 kHz/ch`
2. 依 [spec/](../spec/) 中的感測器手冊將 ADC raw 轉換為實際物理量
3. 產出兩種粒度的 CSV：
   - **高頻（每 cycle 新檔）**：`vibration_sensor_motor{1,2}_<ts>.csv` 與 `electrical_sensor_motor{1,2}_<ts>.csv`，第 1 列為欄位定義、資料從第 2 列開始
   - **低頻（全程 append）**：`low_freq_sensor.csv`，每 cycle 一列，含壓力 + 溫度
4. 提供完整中文文件，方便後續學生接手

## 3. DAQ 讀值轉換原理與公式

### 3.1 從 int16 raw 到電壓

I-8014W 為 16-bit ADC，agent 端設定 `kGain = 0`（[daq_agent_wince.cpp:46](../daq-cpp-code/daq_agent_wince.cpp#L46)），對應 ±10 V 量測範圍。每個樣本送回為 little-endian int16，故：

$$V_{\text{ADC}} = \text{raw}_{\text{int16}} \times \frac{10.0}{32768}$$

對應實作 [decoder.py:decode_payload](../pump_monitor/decoder.py)：

```python
raw   = np.frombuffer(payload, dtype="<i2").reshape(n_samples, n_channels)  # sample-major
volts = raw.astype(np.float32) * (10.0 / 32768.0)
```

**Sample-major interleaved** 是 agent 的 wire format（[daq_agent_wince.cpp:19-22](../daq-cpp-code/daq_agent_wince.cpp#L19-L22)）：第 0 個 sample 的所有通道先送、再送第 1 個 sample 的所有通道。numpy 的 `reshape(n_samples, n_channels)` 直接吃這個排列，每一**列**為一個取樣瞬間、每一**行**為一個通道。

### 3.2 振動：電壓 → 加速度（g）

訊號鏈為**加速規 → SG-3227 → I-8014W**：

| 元件 | 設定 | 影響 |
|---|---|---|
| 603C01 | 100 mV/g 靈敏度（datasheet 主規格） | 1 g 振動 ↔ 100 mV 輸出 |
| SG-3227 | gain DIP = ×1（預設）| AC 耦合，整體增益不變 |

整體轉換式：

$$a\,(g) = \frac{V_{\text{ADC}}}{0.1\,\text{V/g}} = V_{\text{ADC}} \times 10$$

**注意**：實際 SG-3227 的 gain 由現場 DIP switch 決定（×1 / ×10 / ×100）。本專案預設 ×1；若上機後讀值看似 1/10 或 1/100，請至 [pump_monitor/config.py](../pump_monitor/config.py) 將 `IEPE_G_PER_V` 從 `10.0` 調為 `1.0` 或 `0.1`。

### 3.3 電壓：電壓 → 三相電壓（V）

DNM-843VI 預設選用 **600V variant**（DNM-843VI-600V），±600 V 一次側對應 ±10 V 二次側：

$$V_{\text{真實}}\,(\text{V}) = V_{\text{ADC}} \times 60$$

若現場為 800V variant，將 `DNM843_GAIN` 改為 `80.0`。

### 3.4 電流：電壓 → 三相電流（A）

DNM-844-(20A) 預設使用 **20A variant**，±20 A 一次側 → ±10 V 二次側：

$$I_{\text{真實}}\,(\text{A}) = V_{\text{ADC}} \times 2.0$$

DNM-844 系列尚有 5/10/50/200/500/1000/2000A 等變體；對應 `DNM844_GAIN` 為 `0.5 / 1.0 / 5.0 / 20.0 / 50.0 / 100.0 / 200.0`。

### 3.5 壓力與溫度（agent / ET-2215H 已預先轉換）

- **壓力**：DCT 531 register `0x0008`（`Actual pressure`）以 IEEE754 32-bit float 直接給出物理量（單位由 register `0x0044` 決定，預設 bar），agent 已於 header 直接以 `rtuValue1 / rtuValue2` 回傳（[daq_agent_wince.cpp:496-515](../daq-cpp-code/daq_agent_wince.cpp#L496-L515)），**Python 端不需再轉換**。當 `rtuStatus*` 非 OK 時寫 NaN。
- **溫度**：ET-2215H FC04 input register 已是 `(°C × 100)` 的 int16，故 `T = raw / 100.0`；raw = -32768 視為**斷線**寫 NaN（與 [temp_receiver.py:99-111](../temp_receiver.py#L99-L111) 一致）。

### 3.6 預設轉換係數總表

對應實作於 [pump_monitor/config.py](../pump_monitor/config.py)：

| 常數 | 預設值 | 物理意義 |
|---|---|---|
| `ADC_FULL_SCALE_V` | `10.0` | I-8014W gain=0 → ±10V |
| `ADC_FULL_SCALE_RAW` | `32768` | int16 半段 |
| `IEPE_G_PER_V` | `10.0` | 100 mV/g + SG-3227 ×1 |
| `DNM843_GAIN` | `60.0` | DNM-843VI-600V |
| `DNM844_GAIN` | `2.0` | DNM-844-20A |

## 5. 困難與解決方法

### 5.1 C++ agent 為 single-client，如何同時取兩台機器？

**問題**：[daq_agent_wince.cpp:18](../daq-cpp-code/daq_agent_wince.cpp#L18) 設計為 single-client / one-command-per-connection，listen backlog 為 1。同一台 WP-8121 同時連兩條會被擋。

**解法**：改寫 client 端架構，**為兩台機器各開一條獨立 TCP 連線**，分別跑在不同 thread 內：

```python
# pipeline.py
with ThreadPoolExecutor(max_workers=3) as ex:
    f_m1 = ex.submit(_capture_machine1, cfg)   # → 192.168.1.12:9000
    f_m2 = ex.submit(_capture_machine2, cfg)   # → 192.168.1.13:9000
    f_temp = ex.submit(temp_client.read_temperatures, ...)
```

由於兩台機器是兩個不同 IP，single-client 限制只在「同台機器」生效，雙機並行可達真正並行（驗證：dry-run cycle wall-time 約 12 s，含 10 s capture + 2 s 寫檔；若序列化將會 22 s+）。

### 5.2 ET-2215H 長閒置會主動切斷 TCP

**現象**：`temp_receiver.py:84-92` 註解明確指出：「可能是因為長時間閒置 (10 分鐘) 導致設備主動斷開 TCP」。Tpoll = 600 s 完美命中此條件，會持續觸發。

**解法**：在 [pump_monitor/temp_client.py](../pump_monitor/temp_client.py) 鏡像既有的 **2-attempt + reconnect** 策略——第 1 次失敗時 `client.close(); client.connect()`，第 2 次仍失敗才回 `[NaN]*8`。**不引入退避演算法**，避免過度設計。

### 5.3 高頻 CSV 寫入吞吐

**問題**：每 cycle 4 個高頻 CSV，machine2 motor 7-column × 100k 列 ≈ 7 MB；用 `csv.writer` 列迴圈在 Windows 上量測約 8–10 s/檔，四檔即 ~35 s，吃掉太多 cycle 預算。

**解法**：改用 `numpy.savetxt(fmt="%.6f", delimiter=",")`，把列化交給底層 C 實作。實測約 1–2 s/檔，總計 ~5 s。對應實作於 [pump_monitor/csv_writer.py](../pump_monitor/csv_writer.py)。

### 5.4 任意任務失敗不能拖累其他

**需求**：machine1 連線壞掉 → 仍要寫 machine2 + 溫度；ET-2215H 斷線 → 仍要寫兩機 DAQ。

**解法**：`ThreadPoolExecutor` + `Future.exception()` 隔離各任務；外層 `_safe(future, label)` 把例外吞下並 `log.exception(...)`。最後 low_freq 檔**一律 append 一列**（缺值寫 NaN）以保留時間軸連續性。

### 5.5 spec 資料夾 PDF 多為 CJK 編碼，環境工具讀不出文字

**現象**：使用 Read 工具讀 `*_tc.pdf` 時 `pdftoppm` 缺失，且部分 PDF 含 `Adobe-CNS1` 編碼導致 `pdftotext` 報錯。

**解法**：改用 git 內建 `pdftotext -layout`（位於 `C:\Program Files\Git\mingw64\bin\`），逐檔讀出文字後人工整理為轉換係數。CJK 編碼錯誤的部分 fallback 到讀英文版本（如 `8014_9014_en.pdf`）。

### 5.6 fixture bin 為純 payload、無 48-byte header

**現象**：[request-example/](../request-example/) 中的 `.bin` 是 `request-example.py` 寫檔時切掉 header 後的純 payload（800,000 / 2,400,000 bytes），與線上完整封包（48-byte header + payload）格式不同。

**解法**：把 `parse_header()` 與 `decode_payload()` 設計為獨立函式，header 在 [tests/test_decoder_header.py](../tests/test_decoder_header.py) 用 `struct.pack` 手構測試，payload 在 [tests/test_decoder_machine{1,2}.py](../tests/) 直接吃 fixture，互不耦合。

### 5.7 machine2 不接 RTU，但 agent 仍嘗試 Modbus 讀取

**現象**：原 `request-example.py` 對兩台都送 `RTU1=1 RTU2=2`，machine2 端會在 capture 前先被 1 秒 Modbus timeout 阻塞。

**解法**：對 machine2 一律送 `RTU1=0 RTU2=0`，agent 端會直接視為 `RTU_DISABLED`（[daq_agent_wince.cpp:526](../daq-cpp-code/daq_agent_wince.cpp#L526)）跳過 Modbus 讀取，省下兩秒 timeout。
