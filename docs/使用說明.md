# NCKU 水處理廠泵浦監控 — 使用說明

本文件說明如何在家用 PC 上安裝、設定、執行 [pump_monitor](../pump_monitor/) 套件，以及如何驗證輸出與排除常見問題。

---

## 0. 系統概觀（30 秒版）

```
┌──────────────────────┐        START_CAPTURE        ┌──────────────────┐
│ 家用 PC (Windows)    │ ──────────TCP 9000────────→ │ machine1 .12     │
│                      │                              │ 4ch 振動 + 壓力  │
│                      │ ──────────TCP 9000────────→ │ machine2 .13     │
│  pump_monitor.main   │                              │ 12ch 電壓/電流   │
│  迴圈每 600 s 一輪    │                              └──────────────────┘
│                      │ ── Modbus-TCP 502 ─→ ┌────────────────────┐
│                      │                       │ ET-2215H .6 (8 ch) │
│                      │                       └────────────────────┘
│                      │
│  寫入 C:\Users\USER\ │
│  Desktop\data\…csv   │
└──────────────────────┘
```

每 600 秒一輪：對兩台 DAQ 發 `START_CAPTURE`（10 秒高速取樣）+ 對 ET-2215H 讀 8 通道溫度，並行三任務、轉換為實際物理量、寫成 CSV。

## 1. 系統需求

### 硬體
- Windows 10 / 11 PC，與三台設備同網段（預設 192.168.1.0/24）
- 至少 10 GB 可用磁碟空間（每天約產生 2.8 GB CSV）

### 軟體
- Python 3.12 或更新（3.10+ 應該也可）
- pymodbus 3.x
- numpy
- pytest（僅執行測試需要）

### 網路
| 設備 | IP | Port | 協定 |
|---|---|---|---|
| machine1 (WP-8121) | 192.168.1.12 | 9000 | TCP（自訂協定） |
| machine2 (WP-8121) | 192.168.1.13 | 9000 | TCP（自訂協定） |
| ET-2215H | 192.168.1.6 | 502 | Modbus-TCP |

## 3. 設定（[pump_monitor/config.py](../pump_monitor/config.py)）

整個系統只有**一個設定檔**：[config.py](../pump_monitor/config.py)。直接編輯即可，不需 yaml/json。

### 3.1 不常動的設定

| 欄位 | 預設 | 何時要改 |
|---|---|---|
| `M1_IP` | `"192.168.1.12"` | 場域更換 IP 才改 |
| `M2_IP` | `"192.168.1.13"` | 同上 |
| `ET2215H_IP` | `"192.168.1.6"` | 同上 |
| `DAQ_PORT` | `9000` | 配合 C++ agent 端口 |
| `MODBUS_TCP_PORT` | `502` | Modbus 標準 |

### 3.2 採樣參數

| 欄位 | 預設 | 說明 |
|---|---|---|
| `TPOLL_SEC` | `600` | 兩次 cycle 起始的間隔（秒） |
| `SEC` | `10` | 每次 `START_CAPTURE` 的取樣秒數（agent 限制 1–60） |
| `M1_RATE` | `10000` | machine1 每通道採樣頻率 (Hz)，4 ch × 10 kHz = 40 kS/s aggregate |
| `M2_RATE` | `5000` | machine2 每通道採樣頻率 (Hz)，12 ch × 5 kHz = 60 kS/s 安全帶；I-8014W Magic Scan aggregate 上限約 80–90 kS/s，10 kHz/ch 必爆 FIFO |

**約束**：`TPOLL_SEC` 必須 ≥ `SEC` + cycle 處理時間（約 5–15 s）。預設 600 ≫ 25 安全。

### 3.3 物理量轉換係數（**實地校驗後最常需要調整**）

| 欄位 | 目前值 | 對應變體 | 公式 |
|---|---|---|---|
| `ACCEL_SENSITIVITY_MV_PER_G` | `100.0` | 603C01 datasheet 標稱 (固定值) | — |
| `SG3227_GAIN` | `1.0` | SG-3227 DIP switch 增益 (×1 / ×10 / ×100) | — |
| `IEPE_G_PER_V` (衍生屬性) | `10.0` | 由上兩值推算：`1 / (sens/1000 × gain)` | `g = V × 10` |
| `DNM843_GAIN` | `80.0` | DNM-843VI-**800V** | `V_real = V × 80` |
| `DNM844_GAIN` | `100.0` | DNM-844-**1000A** | `A_real = V × 100` |

**常用對照表**（依現場接的變體更換）：

| 元件變體 | gain 應設為 |
|---|---|
| DNM-843VI-600V | `60.0` |
| DNM-843VI-800V | `80.0` |
| DNM-848VI-10V | `1.0` |
| DNM-848VI-80V | `8.0` |
| DNM-848VI-150V | `15.0` |
| DNM-844-5A | `0.5` |
| DNM-844-10A | `1.0` |
| DNM-844-20A | `2.0` |
| DNM-844-50A | `5.0` |
| DNM-844-200A | `20.0` |
| DNM-844-500A | `50.0` |
| DNM-844-1000A | `100.0` |
| DNM-844-2000A | `200.0` |
| SG-3227 gain=×1 加速規 100 mV/g | `SG3227_GAIN = 1.0` → 衍生 `IEPE_G_PER_V = 10.0` |
| SG-3227 gain=×10 加速規 100 mV/g | `SG3227_GAIN = 10.0` → 衍生 `IEPE_G_PER_V = 1.0` |
| SG-3227 gain=×100 加速規 100 mV/g | `SG3227_GAIN = 100.0` → 衍生 `IEPE_G_PER_V = 0.1` |

> 註：SG-3227 的其他 DIP 設定（DC/AC 耦合、IEPE 驅動電流 2/4/6/10 mA）不影響轉換係數，故不在 config 中參數化；但會影響低頻響應與訊號穩定性，請依現場接線手冊設定 DIP 後即不需動到 config。

### 3.4 通道對應

預設假設：

```python
M1_CHANNEL_NAMES = ("motor1_x", "motor1_y", "motor2_x", "motor2_y")
M2_CHANNEL_NAMES = (
    "motor1_Va", "motor1_Vb", "motor1_Vc",   # ch0~2
    "motor2_Va", "motor2_Vb", "motor2_Vc",   # ch3~5
    "motor1_Ia", "motor1_Ib", "motor1_Ic",   # ch6~8
    "motor2_Ia", "motor2_Ib", "motor2_Ic",   # ch9~11
)
```

若現場接線順序不同，編輯這兩個 tuple；同時注意 [pump_monitor/decoder.py](../pump_monitor/decoder.py) 的 `split_machine2()` 假設前 6 ch 是電壓、後 6 ch 是電流。若連此都顛倒，需同步改 decoder。

### 3.5 RTU（壓力）位址

```python
M1_RTU1_ADDR = 1   # motor1 壓力 Modbus slave id
M1_RTU2_ADDR = 2   # motor2 壓力 Modbus slave id
```

machine2 不接 RTU，pipeline 一律送 `RTU1=0 RTU2=0` 讓 agent 跳過 Modbus 讀取（[daq_agent_wince.cpp:526](../daq-cpp-code/daq_agent_wince.cpp#L526)）。

### 3.6 輸出路徑

```python
OUT_BASE = Path(r"C:\Users\USER\Desktop\data")
```

衍生路徑（不需手動設定）：

```
{OUT_BASE}\machine1\         # 振動 CSV
{OUT_BASE}\machine2\         # 電氣 CSV
{OUT_BASE}\low_freq_sensor.csv
{OUT_BASE}\logs\
```

### 4.3 開機自動啟動（Windows 工作排程器）

系統已透過 PowerShell 建立 Task Scheduler 工作，**每次登入後 60 秒自動在背景啟動**，無視窗、log 寫到 `data\logs\`。

#### 工作設定摘要

| 項目 | 值 |
|---|---|
| 工作名稱 | `PumpMonitorLogger` |
| 觸發 | 使用者登入後 **60 秒**（讓網路先就緒）|
| 執行 | `venv\Scripts\python.exe -m pump_monitor.main` |
| 工作目錄 | `C:\Users\USER\Desktop\ncku-daq` |
| 視窗 | 隱藏（無 CMD 視窗，log 寫到 `data\logs\pump_monitor_<日期>.log`） |
| 時間限制 | 無（持續執行不會被自動殺掉） |
| 失敗重試 | 3 次，每次間隔 2 分鐘 |

#### 日常管理指令（PowerShell）

```powershell
# 立刻手動啟動（不重開機也能用）
Start-ScheduledTask "PumpMonitorLogger"

# 立刻停止
Stop-ScheduledTask "PumpMonitorLogger"

# 暫時停用（重開機後不再自啟，手動啟用前都不跑）
Disable-ScheduledTask "PumpMonitorLogger"

# 重新啟用
Enable-ScheduledTask "PumpMonitorLogger"

# 查看目前狀態與上次執行結果
Get-ScheduledTaskInfo "PumpMonitorLogger" | Select LastRunTime, LastTaskResult, NextRunTime
```

`LastTaskResult = 0` 代表成功；`267009`（`0x41301`）代表「執行中」；其他非零值代表異常（查 Windows 錯誤碼或 log）。

#### 手動重新建立 / 修改工作

若要更改設定（如 RATE 改了想延長延遲），以**管理員身分**執行 PowerShell：

```powershell
$ProjectDir = "C:\Users\USER\Desktop\ncku-daq"
$PythonExe  = "$ProjectDir\venv\Scripts\python.exe"

$action   = New-ScheduledTaskAction -Execute $PythonExe -Argument "-m pump_monitor.main" -WorkingDirectory $ProjectDir
$trigger  = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$trigger.Delay = "PT60S"                     # 改成 PT120S 代表 2 分鐘
$settings = New-ScheduledTaskSettingsSet -Hidden -RestartCount 3 `
            -RestartInterval (New-TimeSpan -Minutes 2) `
            -StartWhenAvailable -ExecutionTimeLimit ([TimeSpan]::Zero)

Register-ScheduledTask -TaskName "PumpMonitorLogger" -Action $action `
    -Trigger $trigger -Settings $settings -Force
```

#### 從 GUI 操作

開始選單搜尋 `taskschd.msc` → 工作排程器程式庫 → 找 `PumpMonitorLogger` → 右鍵可啟用 / 停用 / 手動執行 / 刪除。

### 5.2 數值合理性檢查

| 量 | 預期 | 異常徵兆 |
|---|---|---|
| `t_s` | 0 ~ 9.9999 秒，等差 0.0001 | 跳秒 → header `actualSampleRateHz` 偏移 |
| `accel_x_g` 運轉中 | p99 ≈ 0.4 ~ 5 g | 全部 0 → 加速規未供電 / IEPE bias 故障 |

| `temp_ch0_C` | 室溫 + 軸承過熱 = 25–80 °C | NaN → 該通道 PT100 斷線（手冊 raw=-32768 / 網頁 -9999.9） |

| 拔什麼 | 預期行為 |
|---|---|
| machine1 網線 | log ERROR；machine1 振動 CSV 該 cycle 不寫；low_freq 壓力欄 NaN；machine2 + 溫度照常 |

跑過至少一個 cycle 後，執行：

```bash
venv\Scripts\python -m pump_monitor.viz
```

會自動找到**最新一輪 cycle** 的 5 個 CSV，開出 4 張圖：

| 圖 | 內容 | 看什麼 |
|---|---|---|
| 振動檢查 | 4 panel：motor1/2 × X/Y 軸的時域波形（前 0.5 秒） | p99 值是否在 **0.05 ~ 50 g** 區間 → `[OK]`；異常會顯示 `[FAIL]` |
| 電氣 motor1 | 4 panel：V 三相 + I 三相 + V FFT + I FFT | V peak 是否合理（200–800 V）、有沒有 `[SATURATED]`；FFT 主頻是否 50/60 Hz |
| 電氣 motor2 | 同上 | 同上 |
| 低頻檢查 | 2 panel：壓力時間序列 + 溫度時間序列 | 壓力是否落在 0–10 bar，溫度是否落在 -10–100 °C，有幾通道有讀到值 |

每張圖**標題顯示 `[OK]` / `[FAIL]` / `[SATURATED]`** 標誌，方便一眼定位異常。

### 6.1 常用 flag

```bash
# 指定特定 cycle (用檔名上的時間戳)
python -m pump_monitor.viz --ts 20260506_164316

# 不開 GUI、直接存 PNG (適合 SSH / 跑批次 / Windows 排程)
python -m pump_monitor.viz --save --no-show

# 指定 PNG 輸出路徑 (預設為 OUT_BASE/viz/)
python -m pump_monitor.viz --save --save-dir D:\reports
```

### 6.2 用可視化結果判斷 config 是否要調

| 看到 | 大概的解釋 | 建議行動 |
|---|---|---|
| **V `[SATURATED]`**（peak 觸頂 ±量程） | DNM-843 量程比現場電壓小 | 換更大的 variant；或檢查接線是否正確 |
| **V peak 遠小於預期**（例如三相 380V 系統卻只看到 ±50V） | DNM-843 量程比現場電壓大太多，或 `DNM843_GAIN` 設錯 | 對照 [使用說明 §3.3](#33-物理量轉換係數實地校驗後最常需要調整) 變體表，調整 `DNM843_GAIN` |
| **I `[TOO SMALL]`**（peak < 1% 量程） | DNM-844 變體選太大 / 線圈未繞夠圈 / 沒接到 CT | 換更小的 variant 或檢查 CT 接線 |
| **V/I FFT 主頻不在 50/60 Hz** | 訊號被噪音淹沒、或變頻器輸出頻率（VFD） | 若馬達由 VFD 驅動，主頻會隨設定值變化，屬正常 |
| **振動 p99 > 50 g** | `IEPE_G_PER_V` 設太大、或 SG-3227 gain 切錯 | 對照 [使用說明 §3.3](#33-物理量轉換係數實地校驗後最常需要調整)，可能要從 `10.0` 改回 `1.0` |
| **振動 p99 < 0.05 g 但泵浦運轉中** | IEPE bias 異常 / 線斷 / SG-3227 設定錯 | 檢查 SG-3227 LED、IEPE 電流 DIP（2/4/6/10 mA）|
| **壓力欄全 NaN** | RTU 通訊失敗 | 看 [§8 FAQ Q3](#q3壓力欄持續-nan) |

## 8. 常見問題（FAQ）

### Q0：log 一直出現 `machine2 header status=DAQ_ERROR err=203`

**原因**：I-8014W Magic Scan 在多通道下實測 sustainable aggregate 上限約 **80–90 kS/s**。machine2 的 12 ch × 10 kHz = 120 kS/s 超過極限 → FIFO 來不及排空 → overflow → agent 回 `errorCode=203`。

**驗證**（2026-05-06 實測）：

| CH | RATE | aggregate kS/s | 結果 |
|---|---|---|---|
| 12 | 10000 | 120 | ❌ FAIL |
| 12 | 8000  |  96 | ❌ FAIL |
| 8  | 10000 |  80 | ✅ OK |
| 12 | 5000  |  60 | ✅ OK (預設值) |

**解法**：[config.py](../pump_monitor/config.py) 把 `M1_RATE` 與 `M2_RATE` 分開，machine2 用 5000 Hz/ch（安全帶）。machine1 4 ch × 10 kHz = 40 kS/s 沒問題，維持高頻。

**副作用**：machine2 的 Nyquist 從 5 kHz → 2.5 kHz。50/60 Hz 基波 + 1~2 次諧波都還在範圍，深度學習 power signal 訓練無影響；只有「VFD 載波頻率（1–3 kHz）」可能 alias，但這屬高頻雜訊不是 target。

**若上限漂移**：未來換 I-8014W 模組或場域變動，可能 80 kS/s 也撐不住。實測方法見上表 — 用一支 ad-hoc 腳本直接呼叫 `daq_client.request_capture(..., ch=12, rate=R, sec=10, rtu1=0, rtu2=0)` 多試幾個 R 值看哪些回 status=0。

**自動重試**：[pipeline.py](../pump_monitor/pipeline.py) `_capture_with_retry` 已內建：遇 err=203 等 5 秒後再試一次。所以即使設定的 RATE 偶爾 borderline，第二次幾乎都過。

### Q1：cycle wall-time 接近 600 s，差點 overrun

**原因**：磁碟太慢、網路延遲、ET-2215H reconnect 拖太久。

**檢查**：log 內各任務時間戳是否大致重疊（約 10 s）。若某任務超過 30 s 就要追：
- machine1/2：用 wireshark 看 TCP 是否有大量 retransmit
- ET-2215H：是否頻繁出現 reconnect

**緊急處理**：把 `SEC` 暫降為 `5`，cycle 內 capture 量減半。

### Q2：CSV 數值都 0 或都飽和（±10V）

| 症狀 | 通常原因 |
|---|---|
| 全 0 | 訊號鏈某段沒供電（SG-3227 / DNM 模組）；或 I-8014W 通道沒接線 |
| 持續 ±10V | 訊號超過 DNM 量程，要改用更大的 variant；或 IEPE bias 跑掉 |
| 一半通道全 ±10V | 某幾路 CT / 電壓探棒沒接，浮接的通道會被噪音放大到飽和 |

### Q3：壓力欄持續 NaN

```
machine1 RTU1 status=TIMEOUT (motor1 pressure → NaN)
```

**檢查**：
1. WP-8121 的 COM2 是否接到 DCT531？線是否鬆脫？
2. DCT531 baud rate / parity 是否與 [daq_agent_wince.cpp:53-59](../daq-cpp-code/daq_agent_wince.cpp#L53-L59) 一致（9600 8N1，odd parity）？
3. DCT531 slave id 是否真是 1 / 2？用 ICP DAS DCON Utility 掃看看。

### Q4：溫度欄某通道恆 NaN

斷線（PT100 開路）。檢查接線、補釦、PT100 元件本身。

### Q5：想改 Tpoll 為更短間隔（測試時連續取）

```python
# config.py
TPOLL_SEC: int = 30
```

但要注意：每 cycle 產 ~20 MB CSV，30 s 間隔 → 24 小時會產 ~57 GB。確認磁碟夠。

### Q6：想加新通道到 low_freq

1. [pump_monitor/csv_writer.py](../pump_monitor/csv_writer.py) 的 `low_freq_header()` 多加欄位名
2. [pump_monitor/pipeline.py](../pump_monitor/pipeline.py) 的 `append_low_freq_row()` 呼叫處多傳一個值
3. **舊 `low_freq_sensor.csv` 必須改名或刪掉**（首次寫檔才會自動補新 header；舊檔若已寫過，append 模式只會在末尾接新欄位的數字而不更新 header）

### Q7：log 越長越慢？

預設不 rotate，每天約 1–10 KB 增加。若跑超過半年：

```bash
# 月底手動歸檔
move data\logs\pump_monitor_2026*.log archive\logs\
```

### Q8：CSV 檔太大想壓縮

**方法 A**：降低浮點精度

```python
# csv_writer.py
np.savetxt(path, out, fmt="%.4f", delimiter=",", header=...)
```

省約 30% 體積。

**方法 B**：改 parquet（需 `pip install pyarrow`），這要改 `csv_writer.py` 全檔。

**方法 C**（最簡單）：每天結束 zip 一次

```powershell
$today = Get-Date -Format "yyyyMMdd"
Compress-Archive -Path "C:\Users\USER\Desktop\data\machine*\*$today*.csv" `
                 -DestinationPath "C:\Users\USER\Desktop\archive\daq_$today.zip"
```
